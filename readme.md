# shESPFSinit библиотека для инициализации файловой системы esp8266 и esp32

Те, кто используют `esp32`, прекрасно знают, что при первом запуске МК нужно отформатировать файловую систему. Однако, для ее использования нужно перезагрузить `esp32`. Поэтому после первого запуска МК приходится заново прошивать его уже исправленной прошивкой, в которой форматирование отключено.

`shESPFSinit` позволяет избавиться от лишней прошивки МК - она сама определяет, требуется ли форматирование файловой системы, форматирует ее и сама перезагружает МК, если нужно.

***Примечание:** `esp8266` не имеет такой проблемы, но библиотека может использоваться и с ней, например, для скетчей, которые могут использоваться на обоих архитектурах; перезагрузка после форматирования для этой платы не выполняется*

### Основные возможности

- автоматический выбор файловой системы в зависимости от используемого МК - `LittleFS` для `esp8266` и `FFat` для `esp32`;
- возможность ручного указания типа файловой системы:
  - `SPIFFS`;
  - `LittleFS`;
  - `FFat` (доступно только для `esp32`);
- автоматическое форматирование файловой системы при первом запуске или после смены типа файловой системы;
- автоматическая перезагрузка `esp32` после форматирования;
- использование файловой метки с указанием файловой системы в корне файловой системы; по наличию и содержанию этой метки определяется необходимость форматирования файловой системы;

### Настройка платы 

***Примечание:** сказанное здесь актуально для `esp32`; для `esp8266` никаких настроек, кроме выбора размера установленной на вашей плате памяти, делать не нужно*

Для `esp32` можно использовать все три типа файловой системы. Если вы используете `FFat`, то в настройках платы нужно  выбрать в **Partition cheme** схему **Default 4MB with ffat**, если у вас есть модуль `esp32` c 4 МБ флеш-памяти, или **16MB FATFS**, если у вас модуль `esp32` c 16 МБ флеш-памяти;

Для `SPIFFS` и `LittleFS` в **Partition cheme**  нужно выбрать схему **Default 4MB with spiffs** (или другую, соответствующую размеру памяти на борту вашей платы).

Если в **Partition scheme** выбрать схему, не соответствующую используемой вами файловой системы, МК будет срываться в перезагрузку при попытке использования файловой системы.

### Методы библиотеки

конструктор библиотеки
```
shESPFSinit esp_fs;
```

<hr>

инициализация файловой системы
```
bool init();
```
возвращает `true`, если файловая система инициализирована и готова к использованию

<hr>

указание имени файловой метки (по умолчанию используется файл `/fs`)
```
void setLabelFileName(const char *_path);
```
здесь:
- `_path` - путь к файлу метки;

***Важно!!!** файл должен находится в корне файловой системы; в начале имени обязательно должен быть символ `/`*

<hr>

получение имени текущей файловой метки
```
String getLabelFileName();
```

<hr>

установка интерфейса для вывода отладочных сообщений
```
void setSerialObject(Print *_serial);
```
здесь:
- `_serial` - интерфейс для вывода сообщений; это может быть любой интерфейс, наследующий класс `Print` - будь то `Serial`, `File` или какой-нибудь экран;

<hr>

включение/отключение вывода отладочной информации о работе модуля
```
void setLogOnState(bool _on);
```
здесь:
- `_on` - новое состояние опции;

<hr>

получение текущего состояния опции
```
bool getLogOnState();
```
***Примечание:** отключение вывода отладочной информации не отменяет генерацию кода для нее; если возможность вывода отладки вам не нужна совсем, вы можете добавить в скетч `#define SH_LOG_OFF` перед объявлением библиотеки - это позволит немного съэкономить память и уменьшить размер прошивки*
```
#define SH_LOG_OFF
#include <shESPFSinit.h>
```

### Использование файловой системы

Экземпляр файловой системы задается библиотекой
```
ESP_FILESYSTEM
```
и после инициализации его можно использовать как обычно

```
// открытие файла на запись
File file = ESP_FILESYSTEM.open("/test.txt", "w");

// поиск файла
if (ESP_FILESYSTEM.exists("/file.txt");
{
  // файл "/file.txt" существует
}
```
и так далее.

#### Указание типа файловой системы

Тип файловой системы выбирается автоматически - `LittleFS` для `esp8266` и `FFat` для `esp32`. Однако вы можете выбрать тип файловой системы вручную. Для этого перед объявлением библиотеки нужно указать один из следующих макросов:
```
#define SH_USE_SPIFFS   // для использования `SPIFFS`
#define SH_USE_LITTLEFS // для использования `LittleFS`
#define SH_USE_FFAT     // для использования `FFat`
```

Пример использования:
```
#define SH_USE_LITTLEFS
#include <shESPFSinit.h>
```

***Важно!!!** файловая система `FFat` доступна только для `esp32`*

### Возможные проблемы

- Если у вас что-то идет не так - модуль не хочет запускаться, идет циклическая перезагрузка, не отображаются страницы Web-интерфейса, не сохраняются настройки и т.д. проверьте следующее:
  - правильно ли вы выбрали плату; если выбранная плата не соответствует реальному чипу, то прошивка может вообще не заливаться с соответствующим сообщением либо работать с ошибками (не работать вообще);
  - соответствует ли выбранный размер flash-памяти тому, который имеется на плате;
  - соответствует ли выбранная таблица разделов размеру flash-памяти и выбранному типу файловой системы;
  - корректно ли указаны номера пинов для подключения периферии; если, например, для **esp32c3** указать для кнопки пин **GPIO17**, то плата вообще не сможет стартовать;

- Если вы используете плату на `USB_CDC`, и у вас не работает вывод отладочных сообщений, убедитесь, что вы подключили соответствующий интерфейс - для этого используется метод `void setSerialObject(Print *_serial)`; вызывать его следует после инициализации интерфейса; на классических `esp32`/`esp8266` это не требуется, там `Serial` подключен по умолчанию;

- Если вы в затруднении, какую плату вообще выбирать, то можете выбрать следующее:
  - для **esp8266** - **NodeMCU 1.0 (esp-12E Module)**;
  - для **esp-01** с ее куцей памятью можно выбрать **Generic esp8266 Module** и выбрать **Flash Size:** **1MB (FS:64kB OTA:~470kB)** и надеяться, что 470КБ хватит для вашей прошивки :) ;
  - для **esp32** - выбрать **esp32 Dev Module** или, если ваша **esp32** имеет дополнительный буквенный индекс, то соответственно **esp32c3 Dev Module**, **esp32s2 Dev Module** и т.д.;

### Аддоны для esp8266 и esp32

Инструкцию по установке аддонов смотри в документации к **Arduino IDE.**

#### esp8266

Для работы с **esp8266** используется аддон **esp8266 by esp8266 Community**, ссылка для установки:

- http://arduino.esp8266.com/stable/package_esp8266com_index.json

Если не знаете, какую плату выбрать, выбирайте **NodeMCU 1.0 (esp-12E Module)**.

#### esp32

Для работы с **esp32** используется аддон **esp32 by Espressif Systems**, ссылка для установки:

- https://dl.espressif.com/dl/package_esp32_index.json

Если не знаете, какую плату выбрать, выбирайте **esp32 Dev Module** (или **esp32c3 Dev Module**, **esp32s3 Dev Module**, **esp32s2 Dev Module** и т.д. - в зависимости от того, какой процессор используется на вашей плате).

_Для работы с МК **esp32c2**, **esp32c6**, **esp32h2** требуется версия аддона не ниже **3.0**._
